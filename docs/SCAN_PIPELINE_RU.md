# Подготовка сканов — после работающего v0.1

Для первого запуска используйте тестовую комнату. Эта памятка задаёт будущий процесс импорта, но не расширяет текущий milestone.

## Скан → Blender → Unity

1. Сохраните исходный экспорт и фотографии в `SourceScans/<room>/<date>/`, сделайте отдельную резервную копию. До сканирования измерьте хотя бы длину стены, ширину двери и высоту стола.
2. В Blender выберите Metric, Unit Scale 1. Импортируйте скан, сравните минимум два измерения. Исправьте коэффициент масштаба всей модели один раз; затем Apply Rotation & Scale. Экспортное преобразование осей не заменяет проверку размеров.
3. Удалите плавающие фрагменты, закройте нужные отверстия, проверьте normals и отрицательный scale. Отделите оболочку помещения от мебели.
4. Перед заменой стула отдельной моделью удалите его геометрию из общего скана. Восстановите закрытые им пол/стену и текстуру; отключите старый collider. Две наложенные поверхности дадут артефакты и двойные столкновения.
5. Упрощайте mesh с визуальным сравнением силуэтов и углов. Треугольники и материалы учитывайте **для всего видимого кадра**, а не только одного предмета. Жёсткий общий polygon limit задаём после профилирования на Quest.
6. Удалите дубли материалов. Начните с 1K–2K текстур, оставляя больше только там, где проверка в шлеме показывает пользу. Для Android проверьте ASTC compression и mipmaps. Атлас используйте, если он действительно сокращает draw calls без неудобного раздувания текстур. [Форматы текстур Unity](https://docs.unity.com/en-us/engine/6000.0/manual/materials-and-shaders/textures/textures-getting-started/texture-compression-formats/texture-choose-format-by-platform).
7. Для lightmaps подготовьте UV2 без перекрытий. У сканов текстура уже может содержать тени: яркое повторное освещение способно ухудшить результат; сравните варианты материала на устройстве.
8. Создайте отдельные простые collision meshes либо используйте в Unity BoxCollider. Для подвижных объектов — составные primitive colliders или простой convex MeshCollider с Rigidbody. **Исходный LiDAR mesh не назначать collider.** [Rigidbody и colliders](https://docs.unity.com/en-us/engine/6000.0/manual/physics-section/physics-overview/rigidbody/rigidbody-configure-colliders).
9. Для начального пути экспортируйте FBX и текстуры: метры, оси под Unity, без камер/света. GLB/glTF потребует отдельного импортера; выбор этого пути откладываем до реального исходника. `.blend` храните как источник вне Assets, чтобы Unity не зависел от локальной установки Blender.
10. Импортируйте подготовленную модель в `Assets/_Project/Art`, отключите автоматическое Generate Colliders. Проверьте метр по эталону, положите окружение под `Environment/ScanRoot`, оставьте scale родителей и XR равным 1.

Сопоставьте `y=0` с полом класса, задайте безопасную стартовую позицию и заново создайте разрешённые teleport targets. Удаляйте временную комнату только после появления её замены с корректными коллайдерами. Если помещение многоэтажное, одного общего бесконечного plane для пола недостаточно.

## Освещение и оптимизация

Тестовый генератор использует простой свет без теней, чтобы проверить XR. Для класса начните с baked lighting, lightmaps и reflection probes, а для переносимых вещей — light probes. Не помечайте перемещаемые предметы Static. Настройте качество URP и texture compression, замерьте на устройстве; лишь затем решайте, нужны ли LOD, occlusion culling и дополнительные атласы. [Освещение движущихся объектов через light probes](https://docs.unity.com/en-us/engine/6000.5/manual/lighting-overview/direct-and-indirect-lighting/light-probes/moving-objects).

Отдельно измеряйте triangles, batches / SetPass, память текстур, CPU и GPU frame time. Увеличивайте качество по одному параметру; устойчивый кадр важнее детализации. Масштабирование до коридоров и зон — следующая работа после завершения класса.
